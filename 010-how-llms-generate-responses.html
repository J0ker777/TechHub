Ми пишемо ChatGPT:

↳
«Поясни простими словами, що таке REST API»

Через кілька секунд отримуємо цілком осмислену відповідь.

З боку це виглядає так, ніби AI:

  1. прочитав питання;
  2. зрозумів його;
  3. знайшов потрібну інформацію;
  4. сформулював відповідь.

Але технічно все відбувається зовсім не так.

LLM не дістає готову відповідь із якоїсь величезної бази даних.

У спрощеному вигляді вона робить одну операцію знову і знову:

↳
передбачає, який токен має бути наступним.

Сьогодні спробуємо розібратися, як із такого простого принципу виникають відповіді, код, статті та цілі діалоги.

01

1. Що таке LLM

LLM — Large Language Model, або велика мовна модель.

До цього класу належать GPT, Claude, Gemini, Llama та багато інших моделей.

Головна задача мовної моделі:

отримати послідовність токенів
        ↓
оцінити ймовірність наступного токена
        ↓
вибрати один

Наприклад:

Столиця Франції —

модель може оцінити можливі продовження приблизно так:

Париж       97%
Лондон       1%
Берлін       0.5%
Рим          0.3%
...

І вибрати:

Париж

Але на цьому процес не закінчується.

Тепер модель бачить:

Столиця Франції — Париж

і знову прогнозує наступний токен.

Потім ще один.

І ще.

Так поступово формується вся відповідь.

02

2. Але модель не працює безпосередньо зі словами

Для нас текст виглядає так:

REST API використовується для взаємодії систем.

Але модель не працює з текстом у такому вигляді.

Спочатку він проходить через tokenizer.

Текст
  ↓
Tokenizer
  ↓
Tokens
  ↓
LLM
03

3. Що таке токен

Токен — це невелика частина тексту.

Токеном може бути:

  • слово;
  • частина слова;
  • знак пунктуації;
  • число;
  • пробіл або його частина;
  • комбінація символів.

Наприклад, речення:

ChatGPT працює з токенами.

умовно може бути розбито так:

Chat
GPT
 працю
є
 з
 токен
ами
.

Це лише спрощений приклад: конкретний поділ залежить від tokenizer конкретної моделі.

Кожному токену відповідає числовий ID.

Наприклад:

Chat  → 12452
GPT   → 38291
API   → 19432
REST  → 28421

Тобто для моделі наш текст перетворюється приблизно на:

[12452, 38291, 28421, 19432, ...]
04

4. Навіщо взагалі потрібні токени

Комп'ютерній моделі незручно працювати безпосередньо з літерами та словами.

Їй потрібне числове представлення.

Тому маємо ланцюжок:

"Що таке REST API?"
        ↓
     tokenizer
        ↓
      tokens
        ↓
   token IDs
        ↓
       LLM

А після генерації процес відбувається у зворотному напрямку:

LLM
 ↓
token IDs
 ↓
tokens
 ↓
text

Саме цей текст ми бачимо на екрані.

05

5. Token ID — ще не «значення» слова

Може виникнути логічне питання.

Якщо:

REST → 28421

то звідки модель розуміє, що REST пов'язаний з API, HTTP та вебсервісами?

Тут з'являється ще один важливий механізм — embeddings.

Token ID перетворюється на набір чисел — вектор.

Умовно:

REST
 ↓
28421
 ↓
[0.12, -0.81, 0.33, 0.54, ...]

Реальні вектори мають багато вимірів.

У процесі навчання модель формує такі числові представлення, які допомагають їй працювати зі зв'язками та закономірностями між токенами.

Саме тому модель здатна пов'язувати поняття на кшталт:

REST
HTTP
API
JSON
GET
POST
06

6. Контекст — що модель бачить прямо зараз

Тепер найцікавіше.

Уявімо діалог:

User:
Мене звати Олексій.

Assistant:
Приємно познайомитися!

User:
Як мене звати?

Модель може відповісти:

Олексій.

Здається, ніби вона запам'ятала ім'я.

Але на базовому рівні механіка інша.

Під час наступного запиту модель може отримати контекст діалогу приблизно такого виду:

User: Мене звати Олексій.
Assistant: Приємно познайомитися!
User: Як мене звати?

Тобто модель не обов'язково «згадує» попередню фразу так, як це робить людина.

Вона бачить її в поточному контексті.

07

7. Що таке context window

У кожної LLM є обмеження на кількість інформації, яку вона може обробити в одному контексті.

Це називається:

context window — контекстне вікно.

У ньому можуть знаходитися:

System instructions
        +
історія діалогу
        +
повідомлення користувача
        +
документи
        +
результати роботи інструментів
        +
інший переданий контекст

Усе це врешті займає токени.

Умовно:

┌─────────────────────────────┐
│ System instructions         │
│                             │
│ Previous messages           │
│                             │
│ Documents                   │
│                             │
│ User question               │
│                             │
│ Generated answer            │
└─────────────────────────────┘
          Context

Тому фраза:

↳
«AI пам'ятає нашу розмову»

часто технічно означає:

↳
моделі передали потрібну частину попередньої розмови в контексті.

У сучасних AI-системах також можуть існувати окремі механізми довготривалої пам'яті, але це вже надбудова навколо самої LLM.

08

8. Що відбувається всередині моделі

Ми вже отримали токени.

Але як модель визначає, який із них має бути наступним?

Саме тут працює архітектура Transformer.

Один із її ключових механізмів — Attention.

Спрощено він дозволяє моделі визначити:

↳
на які частини контексту варто звернути більше уваги під час обробки поточного токена.

Наприклад:

Сергій поклав ноутбук у рюкзак, тому що він був важкий.

Що означає:

він

Модель повинна врахувати зв'язки між словами та контекстом, щоб сформувати наступне продовження.

Attention допомагає працювати з такими залежностями.

10. Виходить, модель просто вгадує наступне слово?

І так, і ні.

На фундаментальному рівні — вона справді прогнозує наступний токен.

Але слово «вгадує» може створити неправильне враження.

Сучасна LLM має мільярди параметрів і під час навчання засвоює величезну кількість статистичних закономірностей:

мову
структуру тексту
зв'язки між поняттями
шаблони міркувань
структуру програмного коду
фактичні закономірності з навчальних даних

Тому прогноз:

next token

виконується на основі дуже складного представлення всього попереднього контексту.

Саме тому з простого механізму:

predict next token

може виникнути:

стаття
програма
SQL-запит
аналіз документа
пояснення архітектури
діалог
11

11. Чому модель іноді відповідає неправильно

Тепер стає зрозумілим один із головних недоліків LLM.

Модель оптимізована не на правило:

говорити тільки перевірену істину

а передусім на:

генерувати правдоподібне продовження

Наприклад, ми питаємо про неіснуючу технологію:

Розкажи про протокол SuperFastAPI 7.0.

Якщо модель не розпізнає проблему, вона може почати будувати правдоподібну відповідь:

SuperFastAPI 7.0 використовує...

Структура тексту може виглядати абсолютно нормально.

А інформація при цьому може бути вигаданою.

Це одна з причин появи того, що називають:

hallucinations — галюцинації LLM.

12

12. Чому AI може писати код

На перший погляд дивно.

Як передбачення токенів дозволяє написати:

PYTHON
def calculate_sum(a, b):
    return a + b

Але для LLM програмний код — теж послідовність токенів.

Під час навчання модель бачила багато закономірностей виду:

def
function
return
if
for
class
SELECT
FROM
WHERE

і зв'язків між ними.

Тому принцип залишається тим самим:

контекст
   ↓
наступний токен
   ↓
наступний токен
   ↓
наступний токен

Просто результатом є не природна мова, а код.

13

13. Де тоді знаходяться знання моделі?

Це цікаве питання.

У звичайній системі ми звикли думати:

Application
    ↓
Database
    ↓
SELECT
    ↓
Result

У LLM немає таблиці:

Questions
-------------------------
question | answer

Знання, отримані під час навчання, розподілені у вагах моделі — величезній кількості числових параметрів.

Умовно:

Training data
      ↓
   Training
      ↓
Model parameters
      ↓
     LLM

Тому модель не шукає готовий рядок:

"Столиця Франції" → "Париж"

Вона генерує відповідь на основі закономірностей, закодованих у параметрах моделі та поточного контексту.

14. А звідки тоді AI бере актуальну інформацію?

Сама LLM не обов'язково знає, що сталося сьогодні.

Наприклад:

16. Найцікавіший парадокс LLM

Уся складність сучасних мовних моделей у результаті зводиться до дуже простої задачі:

↳
Який токен має бути наступним?

Але якщо:

  • модель достатньо велика;
  • навчальних даних достатньо;
  • архітектура достатньо потужна;
  • контекст достатньо хороший;

то з багаторазового передбачення наступного токена виникає поведінка, яка зовні може нагадувати розуміння та міркування.

Саме це і робить сучасні LLM настільки цікавими.

17

Що варто запам'ятати

LLM працює не зі словами, а з токенами.

Text → Tokens → Numbers → Model

Модель отримує контекст:

Instructions
+
Conversation
+
Documents
+
User request

Transformer аналізує зв'язки всередині цього контексту.

Після цього модель прогнозує:

Next Token

додає його до відповіді й повторює процес:

Token
 ↓
Token
 ↓
Token
 ↓
Token
 ↓
Answer

Тому LLM — це не база готових відповідей.

І не пошукова система.

У своїй основі це величезна математична модель, навчена передбачати продовження послідовності токенів.
